В FOCA-rs 2.0 встроено 42 источника: 39 записей в `SOURCES` (`crates/foca-engine/src/scan/sources.rs`: 37 отображаются в «Настройки → Источники» пятью группами + свёрнутая «Дополнительно, с ключом», ещё 2: `dns` и `fuzz`: включаются модулями профиля), плюс 3 пассивных API-коллектора с ключами, добавленных в 2.0 (`vt` VirusTotal v3, `st` SecurityTrails и `github` GitHub Code Search). Дополнительные источники также можно подключать через [плагины в песочнице](settings-network.md#плагины-в-песочнице).

Google как прямой источник не используется ([ADR-0007](../../adr/0007-search-engines-via-webview.md)); выдача Google доступна только опосредованно: через Startpage.

Колонки: Доступ, нужен ли ключ или встроенный браузер; К цели: обращается ли источник к сайту цели (пассивный: нет); Профили: где опрашивается по умолчанию.

Источники, обращающиеся к цели (`crawler`, `ports`, `subdomains`, `tls`, `fuzz`), автоматически исключаются в «Пассивном» профиле. `subdomains` и `tls` можно пропустить кнопкой «Пропустить» до конца этапа «Порты». SaaS-карта, арендатор Microsoft 365, почтовые политики, CDN/облака и история сертификатов (модуль `infra`) работают во всех профилях через резолвер устройства и открытые эндпоинты Microsoft, не обращаясь к серверам цели. Источник, выключенный в «Настройки → Источники», не опрашивается ни одним этапом.

## Обход сайта

Краулер работает только в профилях «Стандартный» и «Полный». Он начинает с главных страниц целей, строк `Sitemap:` из robots.txt и `/sitemap.xml` (включая индексы и `.gz`).

- **Лимиты** («Настройки → Обход сайта» или блок «Дополнительно» мастера для одного скана): по умолчанию глубина 5, 1000 страниц и 20 минут за скан. Если обход упёрся в лимит, следующий скан продолжит с непройденных страниц («Продолжать незавершённый обход»).
- **Ловушки**: календари, бесконечные фильтры и параметры сессий обходятся по шаблону адреса с лимитом; метки отслеживания отбрасываются; ссылки выхода и удаления не открываются; `rel=nofollow` учитывается, если включено.
- **Зеркала**: стартовый хост, который перенаправляет на другой стартовый хост или отдаёт ту же стартовую страницу (обычно `www` и домен без него), обходится один раз: с него запрашиваются только новые для него пути.
- **Темп**: краулер соблюдает сетевой лимит запросов. Ответ 429 или 503 вдвое снижает темп для этого хоста и выдерживает `Retry-After`; при повторах хост больше не обходится в этом скане, экран скана это показывает. Защиту от ботов и капчи FOCA-rs не обходит. Пока скан на паузе, обход ждёт; лимит времени при этом идёт, поэтому после долгой паузы обход заканчивается, а следующий скан его продолжит.
- **Сайты-приложения** (React, Flutter и подобные): если страница оказалась оболочкой приложения почти без ссылок, Android отрисовывает её в скрытом встроенном браузере (до 30 страниц за скан) и берёт ссылки из готовой страницы. Версии для компьютера и CLI используют HTML как есть, а скан предупреждает, сколько таких страниц не удалось отрисовать.
- **Файлы во внешних хранилищах**: ссылки со страниц скоупа на Google Drive, Google Docs/Sheets/Slides, OneDrive, Dropbox и SharePoint считаются документами цели. Скачиваются ровно эти файлы (открытая папка: до 200 файлов, всего до 1000), эти файлы делят лимит документов скана с остальными источниками, больше ничего в хранилище не просматривается, в журнале запросов такие запросы помечены `linked_storage`. Закрытые файлы отмечаются как закрытые, а не как ошибки. Google Docs/Sheets/Slides скачиваются как экспорт (PDF, DOCX, XLSX): их метаданные пишет Google, поэтому авторы по ним не определяются. Выключается переключателем «Файлы во внешних хранилищах по ссылкам с сайта».
- **Фото для EXIF**: до 300 изображений и 200 МБ за скан (не больше лимита трафика), сначала форматы камер; значки и миниатюры пропускаются. Изображения из всех источников считаются по этим лимитам, а не по лимиту документов. Если «Фото для EXIF» выключено, ссылки на изображения пропускаются, если только типы документов запуска не просят изображения.
- **Ссылки внутри документов**: ссылки в скачанных документах (в PDF это URI-аннотации) на документы скоупа или файлы связанных хранилищ тоже скачиваются, до 2 шагов вглубь, в пределах лимита документов.
- **Происхождение**: у каждого такого документа в карточке видно, откуда он: страница со ссылкой, документ, где нашлась ссылка, хранилище и пометка об экспорте Google.

## Признаки технологий сайта

Источник `recon` определяет технологии сайта по правилам webappanalyzer и примерно 130 собственным правилам. Что он читает, зависит от профиля:

| Признак | Откуда | Профили |
|---|---|---|
| Заголовки, cookie, `<meta>`, HTML, `<script src>`, адрес страницы | главная страница (в Пассивном: копия из архива) | все |
| Содержимое JS-файлов | скрипты, которые этап и так скачивает (первые 512 КиБ каждого) | все |
| Видимый текст, CSS | текст главной, встроенные `<style>` и до 5 таблиц стилей того же сайта | все |
| Издатель TLS-сертификата | TLS-проверка этапа «Сеть» | Стандартный, Полный |
| robots.txt | robots.txt из архива | все |
| JS-переменные, DOM-селекторы, хосты запросов | одна отрисовка главной каждого сайта в скрытом браузере Android и страницы-приложения, которые уже отрисовал краулер | Стандартный, Полный, только Android |
| Плагины, темы, модули | пути ресурсов в скачанном HTML: WordPress `/wp-content/plugins/<slug>/` и `themes/`, Drupal, Joomla, Magento, PrestaShop; версия из `?ver=` (версия ядра WordPress не считается) | все |
| readme плагина | `Stable tag` в `readme.txt` до 30 плагинов WordPress | Полный |

Отрисовка читает только нужные правилам переменные и селекторы одним скриптом, который останавливается через 1,5 с и ничего не меняет на странице. Настройки → Обход сайта → «Главных страниц через браузер» ограничивает число отрисовок за скан (по умолчанию 10, 0 выключает). В CLI и настольной версии браузера нет: журнал скана отмечает, что браузерные признаки не проверены. У каждой технологии видно, какими признаками она найдена, а плагины сгруппированы под своей CMS в разделе «Данные → Технологии сайта».

## Статусы источника

На экране скана и в «Настройки → Источники»:

| Статус | Значение |
|---|---|
| ответил (`ok`) | данные получены (`· найдено N`) |
| ошибка / нет ответа | сбой сети или таймаут; скан идёт дальше без источника |
| капча / заблокировано | поисковик показал проверку или заблокировал IP, см. [капча](settings-network.md#капча-и-ручная-проверка) |
| нужна проверка | капча во встроенном браузере: кнопка «Пройти проверку», затем повтор источника |
| лимит запросов | HTTP 429 или 503 (например OTX): источник выдерживает `Retry-After`, замедляется, а после повторных ограничений останавливается в этом скане; собранное сохраняется |
| пропущен | пропущен пользователем («Пропустить источник») или выключен |
| нет ключа (`no_key`) | источник с ключом без ключа: пропускается без ошибки скана |
| нужен встроенный браузер | `startpage`, `brave_web`, `yahoo`, `searx_pool` вне Android (CLI, `foca serve`): статус `unavailable` |
| пропущен в фоне (`skipped_headless`) | WebView-источник пропущен при автономном фоновом перескане без открытого окна |
| недостоверно | скан портов через локальный VPN/прокси, см. [VPN и порты](settings-network.md#vpn-adguard-и-недостоверный-скан-портов) |

## Глубокий Common Crawl

Публичный индекс Common Crawl ненадёжен: снимки случайно отвечают 400/404/502/504 между нормальными ответами, и быстрый проход по всем снимкам примерно наполовину не удаётся. Поэтому FOCA-rs:

- обращается к индексу не чаще раза в 3 секунды (`settings.search.cc_pace_s`, против публичного индекса не меньше) и повторяет 5xx/400/таймауты с растущей паузой;
- считает 404 отсутствием снимков сайта и через `showNumPages` пропускает пустые снимки до загрузки страниц;
- фильтрует по статусу и типу файла на сервере, а каждый адрес оставляет один раз с первой и последней датой;
- после сбоя соединения (отказ, обрыв TLS) повторяет снимок один раз, а после трёх недоступных снимков подряд заканчивает проход в этом скане;
- в проходе за N лет останавливается, если в шести самых новых ответивших снимках домена нет (в более старых его не будет тоже); «все снимки» проверяет каждый;
- глубокий проход (последние N лет или все снимки) идёт в фоне: он стартует с этапом «Поиск», но этап заканчивается вместе с остальными источниками. Проход продолжается на следующих этапах в пределах `settings.search.cc_minutes` (по умолчанию 5 минут за скан); найденные позже документы скачиваются в начале следующего этапа, а то, что не успело через 10 секунд после начала отчёта, продолжится в следующем скане;
- кэширует результаты по домену на устройстве: повторный скан в течение 24 часов не отправляет запросов по готовым снимкам, а незаконченный проход продолжается в следующем скане;
- если адрес из Common Crawl сейчас не открывается, берёт копию из Wayback.

## Отложенные поиски

Если все поисковики показывают капчу, дорки, которые не смог выполнить ни один поисковик, сохраняются в проекте и повторяются сами: медленно, по одному, через `settings.search.dork_retry_min` минут (по умолчанию 15), пока скан идёт, и в следующем скане, где они выполняются первыми. Экран скана показывает «Поисков отложено: N» и кнопку **Повторить сейчас**. Капчи никогда не решаются автоматически.

## Ключи API

Ключи, только опция ([ADR-0010](../../adr/0010-api-keys-optional.md)): без них работает всё, кроме источников с ключами (Brave Search API, свой SearXNG ([настройка](searxng.md)), Shodan, VirusTotal v3, SecurityTrails, GitHub Code Search), повышенных лимитов (например, OTX) и опциональных облачного ИИ / Telegram и Webhook.

Ключи вводятся только в «Настройки → Ключи API» (`/settings/keys`), хранятся в Android Keystore (`AES-256-GCM`, `KeyVault.kt`), вычищаются из `request_log` и архива логов и никогда не попадают в файлы проектов или отчёты.

## Развитие источников до 2.0

- **1.1:** Yahoo и пул публичных SearXNG (через встроенный браузер), общая очередь дорков с failover, OR-группами и кэшем 24 ч, единая кнопка «Пройти проверку (N)».
- **1.2:** Перебор и перестановки поддоменов (`subdomains`), TLS/X.509-инспектор (`tls`), health-пинг пула SearXNG, инфраструктура DNS (`infra`).
- **1.4:** Веб-аудит (`webaudit`) с учётом уровня доступа.
- **2.0 beta:** глубокий Common Crawl с продолжением, кэшем по домену и запасной копией из Wayback, отложенные после капчи дорки («Повторить сейчас»), свои экземпляры SearXNG раньше публичного пула, Brave Search API как поисковик для дорков, общее замедление при 429/503 в поисковых источниках, обход сайта (`crawler`) с файлами во внешних хранилищах и ссылками внутри документов.
- **2.0:** Пассивные API-коллекторы VirusTotal v3 (`vt`), SecurityTrails (`st`) и GitHub Code Search (`github`), опциональные WebView-скриншоты с `pHash`-кластеризацией и расширяемые плагины в песочнице (`/settings/plugins`). См. [дорожную карту](../ROADMAP.md).
