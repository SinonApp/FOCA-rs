# Документы: форматы, форензика, поиск, правила, офлайн-разбор

↑ [Руководство пользователя](README.md) · [Документация](../README.md)

FOCA-rs разбирает широкий спектр офисных, архивных, почтовых, издательских и медиаформатов и показывает в карточке документа то, что файл хранит помимо видимого текста: цифровые подписи и украинский КЕП, старые ревизии PDF, текст под закраской, скрытое содержимое, встроенные OLE-объекты и персональные данные. Те же сведения кратко: в офлайн-справке приложения (⋮ → Помощь → Документы и форензика).

## Форматы

| Формат | Что извлекается |
|---|---|
| Office (`DOC`/`DOCX`, `XLS`/`XLSX`, `PPT`/`PPTX`), OpenDocument (`ODT`/`ODS`/`ODP`), `RTF` | Автор, изменивший, компания, шаблон, пути на диске и UNC, принтеры, исправления и комментарии, скрытый текст (`w:vanish`), скрытые строки/столбцы/листы, подключения к данным, сводные таблицы, подписи XML-DSig и макросов VBA; глубокий разбор бинарных OLE2 (`\x01Ole10Native`, оригинальные/временные пути, история сохранений `SttbSavedBy`) |
| `PDF` | Автор, программы, XMP-история правок, ревизии инкрементальных сохранений с диффом текста, текст под закраской, подписи (`/ByteRange`, CAdES, метки RFC 3161 TSA), «скан без текстового слоя», встроенные изображения с EXIF |
| `Visio` (`VSDX`/`VSD`), `Publisher`, `InDesign`, `WordPerfect`, `Works` | Метаданные, страницы, комментарии, подключения к данным Visio, XMP |
| `EPUB` | Контейнер (`META-INF/container.xml`) и `.opf` (Dublin Core `creator`, `contributor`, `publisher`, `date`, `identifier`, генератор), рекурсивный разбор встроенных обложек и иллюстраций |
| `PSD` (Adobe Photoshop) | Заголовок `8BPS` и блоки ресурсов `8BIM`: история правок XMP, TIFF/EXIF, JPEG-миниатюра, встроенная подпись |
| `MP3` | Теги `ID3v1` и `ID3v2.2/2.3/2.4` (автор/композитор, издатель/студия, программа кодирования, комментарии) + рекурсивный EXIF/GPS из встроенной обложки (`APIC`/`PIC`) |
| Ярлыки Windows (`LNK`) | Имя компьютера, MAC-адрес, серийный номер и метка тома, локальный и сетевой (`UNC`) путь |
| Письма (`EML`/`MSG`) | Отправитель, получатели, `Reply-To`, `Message-ID`, почтовая программа, цепочка `Received` с внутренними серверами и IP, `X-Originating-IP`, арендатор Microsoft 365, адреса X.500, вложения (разбираются рекурсивно) |
| Календари (`ICS`), контакты (`VCF`) | Организатор, участники, места, ссылки на онлайн-встречи; телефоны, адреса, даты рождения (маскируются); фото внутри VCF |
| Фото и видео (`JPEG`, `PNG`, `TIFF`, `HEIC`, `MP4`, `MOV`) | Камера/телефон, серийный номер, дата, GPS, несовпадение миниатюры EXIF с основным фото |
| Архивы (`ZIP`, `7z`) | Список файлов, рекурсивный разбор вложенных документов (до 2 уровней под общим бюджетом байт/файлов), обнаружение опасных путей (`../`, Zip-Slip) |

Типы файлов для поиска в сети выбираются в мастере запуска (Дополнительно → Типы документов, по группам). Большие видео скачиваются частично: только блоки метаданных.

Все основные контейнеры (`PDF`, `OOXML`, `ODF`, `JPEG`, бинарные `OLE2` `.doc`/`.xls`/`.ppt`/`.vsd`/`.pub` и медиа `ISO-BMFF` `.mp4`/`.mov`/`.heic`) поддерживают очистку метаданных с автоматической самопроверкой «До / После», см. [Гигиена и очистка документов](analytics-and-hygiene.md#гигиена-и-очистка-документов).

## Форензика в карточке документа

В карточке (`Данные → Документы → документ`) под метаданными расположен раздел «Форензика». Секции свёрнуты для удобства на экране телефона; справа: число записей и самая серьёзная метка:

| Секция | Что показывает |
|---|---|
| **Подписи и КЕП** | Подписант, должность, организация, ЄДРПОУ, РНОКПП (только маска), АЦСК, время подписи, метка TSA и расхождение с ней, «правки после подписания», сверка хеша (SHA-2) |
| **Плохое замазывание** | Страница, цвет заливки и короткий фрагмент текста, оставшийся под прямоугольником |
| **Ревизии PDF** | Версии файла: кто и в какой программе сохранял, удалённые (`−`) и добавленные (`+`) строки |
| **Скрытое содержимое** | Скрытый текст Word (`w:vanish`), скрытые строки, столбцы и листы Excel с данными |
| **Подключения к данным** | Подключения к базам, файлы `.odc`, сводные таблицы (кто обновлял, источник), внешние ссылки диаграмм |
| **Заголовки письма / Ярлык / Календарь / Контакты / Медиафайл** | Артефакты формата (см. таблицу выше); в цепочке `Received` подсвечены внутренние адреса |
| **Персональные данные** | Типы, количества и маски найденных значений |
| **Облачные ссылки и токены** | Google Drive, SharePoint, Notion, Jira, Azure/S3 и др.; токены в адресах маскированы, SAS и вебхуки: критичны |
| **История правок (XMP)** | В какой программе создан, конвертирован и сохранён; `DocumentID` и `DerivedFrom` |
| **Вложения / Файлы в архиве** | Вложенные файлы и их тип; опасные пути архива (`Zip-Slip`) и встроенные объекты `Ole10Native` |

Для каждого сигнала создаётся находка с кодом (`doc.bad_redaction`, `doc.modified_after_signing`, `mail.internal_relay`, `pii` и др.). На карточке находки: пояснение кода и кнопка «К документу». Флаги в списке документов: щит, форензика, человек, персональные данные; фильтр «Только с находками» учитывает и их.

## Персональные данные и маскирование

Ищутся РНОКПП (ІПН), коды ЄДРПОУ, IBAN, номера платёжных карт, паспортов и ID-карт, телефоны и грифы ограничения доступа. Номера проверяются по контрольным суммам (РНОКПП, ЄДРПОУ, IBAN mod-97, алгоритм Луна для карт).

- **Значения маскируются до сохранения:** в базе проекта, индексе FTS5, отчёте и экспорте хранятся только маски (`••••••••90`). Полный номер показать нельзя: его нет на устройстве; «показать секрет» к ПДн не применяется.
- На документ создаётся одна находка на каждый тип данных со счётчиком. ЄДРПОУ организаций публичен: уровень «Инфо».
- В отчёте выводятся только типы и количества.

## Поиск по тексту документов

**Данные → Документы → «Поиск по тексту документов»** (или глобальный поиск: раздел «В тексте документов»). Работает полностью без сети по индексу SQLite FTS5:

- Несколько слов: документ содержит все; `"фраза в кавычках"`: точная фраза; `-слово`: исключить; `енерг*`: начало слова.
- Совпадения подсвечены в коротком фрагменте; ПДн и секреты во фрагменте автоматически скрыты с пометкой («В фрагменте скрыто: IBAN, телефон»).
- По переключателю «Включая корзину» ищутся и удалённые из проекта документы.

## Правила поиска

**⋮ → Правила поиска** или Скоуп → Анализ документов → Правила поиска: настройка проекта:

- **Готовые наборы:** документы госорганов Украины (номера наказів, вихідні номери, інвентарні номери ДСК), учётные данные в тексте, внутренняя инфраструктура (UNC, RDP/SSH-адреса), криптокошельки, ПДн в свободной форме.
- **Свои правила**, регулярные выражения: название, шаблон, важность, «без учёта регистра», «маскировать значение». Группа `(?P<v>…)` задаёт значение для находки. «Проверить на тексте» показывает совпадения на вашем примере (значения маскируются).
- Ошибки шаблона отображаются под полем правила. Лимиты: шаблон до 512 символов, до 64 правил, шаблон не должен совпадать с пустой строкой.
- После «Сохранить и пересчитать» находки `doc.user_rule` появляются сразу, без нового скана.

## Разбор файлов без сети

**Проекты → «Разобрать файлы без сети»** (или ⋮ в любом месте):

1. Выберите назначение: новый проект (название, необязательный домен для шаблона e-mail) или текущий.
2. **Выбрать папку** (рекурсивно через Android SAF) или Файлы или ZIP.
3. **Разобрать**: прогресс по файлам, кнопка «Отмена» (уже разобранные файлы сохраняются).
4. Итог: сколько добавлено, дубликаты, что пропущено и почему → Открыть проект.

Сеть не используется: файлы копируются в приватную папку приложения, разбираются локально и не покидают телефон; временные копии удаляются после разбора. Лимиты: до 500 файлов и 512 МБ за раз, файл до 100 МБ, тайм-аут на файл 30 секунд.

## Опциональный офлайн-OCR (флейвор `play`)

Для сканированных PDF и изображений без текстового слоя (`< 40` извлечённых символов) в сборке `play` доступен опциональный 100% локальный OCR на базе Google ML Kit (`com.google.mlkit:text-recognition`):

- **Выключен по умолчанию** (`settings.ocr.enabled = false`). Включается в «Настройки → Базы сигнатур и OCR» (`/settings/signatures`), там же задаются лимиты `max_pages` (по умолчанию 10) и `max_mb` (по умолчанию 15 МБ).
- Выполняется полностью на устройстве без облачных API; распознанный текст (до 256 КиБ на файл) попадает в полнотекстовый индекс FTS5 и проверяется детектором маскируемых ПДн и форензики.
- В чистой свободной сборке `foss` (F-Droid / прямые релизы `GPL-3.0`) ML Kit отсутствует и OCR возвращает статус `unavailable_in_foss_build`.

## Ограничения

- Подписи внутри старых бинарных `.doc`/`.xls` (OLE `\x05DigitalSignature`) не читаются; цепочка сертификатов и отзыв (CRL/OCSP) не проверяются.
- Поля КЕП (РНОКПП, ЄДРПОУ) разбираются по ETSI EN 319 412-1 и национальному профилю сертификатов; критичные случаи проверяйте официальными средствами валидации.
- Скрытый текст Word, заданный исключительно через стили (а не `w:vanish`), не определяется.
- Детектор замазывания оценивает ширину символов приблизительно (~0,5 em), не заходит во вложенные формы XObject, не учитывает прозрачность/обрезку и пропускает прямоугольники > 80 % страницы.
- В индекс FTS5 попадают первые 64 КиБ текста каждого документа; сканы ищутся по тексту только при включённом OCR во флейворе `play`.
- Архивы `RAR` не поддержаны (чистый Rust разбирает `ZIP` и `7z`).
