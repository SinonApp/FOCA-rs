## Коротко

| Профиль | Время* | Уровень доступа | К сайту цели |
|---|---|---|---|
| **Пассивный** | ~5 мин | `external` | никогда: только сторонние сервисы и архивные копии |
| **Стандартный** | ~25 мин | `target` | обычные запросы: скачивание документов, DNS, TCP-живость, обход сайта, инспекция TLS |
| **Полный** | ~45 мин | `active` | + активная фаза: AXFR, обход NSEC, скан портов, поиск забытых файлов, активный веб-аудит |
| **Свой** | - | по выбранным модулям | как у самого «сильного» выбранного модуля |

\* Оценка из мастера запуска (`ui/screens/launch.js`), реальное время зависит от сети, прокси/Tor и размера цели.

Модули по умолчанию (ядро `default_modules` в `crates/foca-engine/src/scan/mod.rs`, сверено с `PROFILE_MODS` в `ui/screens/launch.js`):

- все профили: `search`, `crt`, `wayback`, `cc`, `meta`, `analysis`, `ct`, `recon`, `infra`;
- не пассивные (Стандартный и Полный): + `crawler`, `dns`, `docs`, `alive`, `subdomains`, `tls`;
- полный: + `axfr`, `ports`, `fuzz`, `nsec`.

## Что делает каждый профиль в сети

**Пассивный**: запросы идут только к сторонним сервисам (поисковики, веб-архивы, CT-журналы, сервисы поддоменов, RDAP, Shodan InternetDB, grep.app и опциональные ключи API вроде VirusTotal, SecurityTrails, GitHub Code Search):

- дорки в поисковиках (Startpage, Brave, Yahoo и публичные SearXNG: через встроенный браузер), URL из архивов и сервисов разведки;
- документы с сайта цели скачиваются копией из Wayback (`id_`-снимок), сам сайт не запрашивается; нет копии: задача «ошибка», цель не тронута;
- поддомены из CT и сервисов поддоменов, их адреса: через резолвер устройства/DoH (не через NS цели);
- прямые цели `ip`, `cidr` и `range` проходят пассивное обогащение через RDAP (сеть и ASN) и Shodan InternetDB (порты, CPE, CVE из кэша);
- разведка сайта по архивной копии главной/favicon/скриптов, `robots`/`sitemap`/`security.txt` из CDX;
- инфраструктура по DNS (модуль `infra`): SaaS-сервисы по TXT/SPF/MX/CNAME, арендатор Microsoft 365 (только эндпоинты Microsoft), почтовые политики (BIMI, MTA-STS по DNS, TLS-RPT, CAA, DNSSEC), CDN/облака по диапазонам, кандидаты origin за CDN, история сертификатов (CT), роли хостов по именам;
- пассивные плагины в песочнице (`net:passive`) также работают через `NetClient` с жёсткой блокировкой целевых хостов.

Гарантия, на уровне ядра: в пассивном уровне (`Access::Passive`) `NetClient` отказывает в любом запросе к хосту цели или исключения, в том числе после редиректа ([ADR-0009](../../adr/0009-passive-never-touches-target.md)).

**Стандартный** = Пассивный + обращения к целям скоупа:

- скачивание публичных документов с сайтов целей;
- DNS-сводка доменов целей: записи A/AAAA/MX/NS/TXT/SOA, SPF/DMARC/DKIM, висящие CNAME;
- проверка живости хостов с подтверждением протокола (`tcp_alive_checked`, с защитой от ложных срабатываний локального VPN);
- краулер: обход страниц сайта цели (глубина и лимиты: в мастере → «Дополнительно»);
- **перебор поддоменов** (топ-1500 по умолчанию, словарь: в мастере) и перестановки известных имён (включая токены из метаданных документов), PTR адресов скоупа; wildcard-зоны распознаются по уровням, ложные хосты отбрасываются;
- **проверка TLS-сертификатов** открытых TLS-портов живых хостов скоупа и загрузка политики MTA-STS;
- **веб-аудит** (`GET` к `.js.map`, Swagger/OpenAPI, Spring Actuator, `openid-configuration`);
- опциональные WebView-скриншоты и `pHash`-кластеризация живых веб-сервисов при явном включении `settings.recon.screenshots = true` (выключены по умолчанию; в «Пассивном» никогда не выполняются).

**Полный** = Стандартный + активная фаза (только скоуп, исключения не трогаются):

- **AXFR**: попытка получить всю зону у NS цели;
- **обход NSEC** подписанной зоны у NS цели и расширенный перебор поддоменов топ-5000;
- **скан портов** TCP connect живых хостов (до 20 хостов, топ-100 по умолчанию или топ-1000), баннеры и версии; при признаках локального VPN результат помечается «Недостоверно», см. [Настройки и сеть](settings-network.md#vpn-adguard-и-недостоверный-скан-портов);
- **поиск забытых файлов на сайте** (`foca-fuzz`): документы, бэкапы, `.env`/`.git`/`.DS_Store`, листинги, скрытые vhost, пути CMS, щадящий перебор с калибровкой мягкого 404 и автостопом при 429/403/5xx;
- облачные хранилища из найденных ссылок проверяются на открытый листинг;
- **аудит TLS**: TLS 1.0/1.1 и слабые шифры, STARTTLS (25/587/143/110/21/5432/3389), проверка по IP без SNI (только адреса скоупа, не общий хостинг): подтверждение origin за CDN; разведка нестандартных веб-портов `8080`/`8443`/`3000`/`9000`/`5601`/`9200`;
- **активный веб-аудит**: `OPTIONS`, `TRACE`, `PROPFIND` и проверка CORS подставным `Origin` (`PUT` и `DELETE` не отправляются никогда).

Плановый перескан (мониторинг) запускает только Пассивный или Стандартный профиль: активный уровень по расписанию ядро отклоняет.

## Модули профиля «Свой»

Из `MODS` мастера (`ui/screens/launch.js`):

| id | Модуль | Тип |
|---|---|---|
| `search` | Поисковые API (Startpage, Brave, Yahoo, публичные SearXNG: через встроенный браузер; Brave API, свой SearXNG, VirusTotal, SecurityTrails, GitHub: по ключам) | внешний |
| `crt` | Сертификаты `crt.sh`: поддомены из CT | внешний |
| `wayback` | Веб-архив: старые копии страниц и файлов | внешний |
| `recon` | Разведка сайта (в «Пассивном»: по архивной копии; в «Стандартном»/«Полном»: вживую + опц. скриншоты) | внешний / к цели |
| `infra` | Инфраструктура по DNS: SaaS и Microsoft 365, почтовые политики, CDN, история сертификатов, роли хостов | внешний |
| `dns` | DNS-записи и поддомены у серверов имён цели | к цели |
| `docs` | Скачивание документов с сайтов целей | к цели |
| `alive` | Проверка живости (TCP) | к цели |
| `subdomains` | Перебор поддоменов и перестановки (словарь: в мастере) | к цели |
| `tls` | Проверка TLS-сертификатов | к цели |
| `axfr` | Перенос зоны (AXFR) | активный |
| `nsec` | Обход зоны (NSEC) | активный |
| `ports` | Скан портов (TCP) | активный |
| `fuzz` | Поиск забытых файлов на сайте (подмодули `docs`, `backups`, `exposed`, `dirlisting`, `vhost`, `cms`) | активный |

## Этапы скана

9 этапов: `STAGES` в `crates/foca-engine/src/scan/mod.rs` (прогресс = номер этапа / 9):

| # | id | Этап | Что происходит |
|---|---|---|---|
| 1 | `search` | Поиск | Источники параллельно выдают URL документов и поддомены (общая очередь дорков, failover при капче) |
| 2 | `download` | Загрузка | Скачивание (или архивная копия в «Пассивном»), лимиты, SHA-256, дедуп |
| 3 | `meta` | Извлечение метаданных | `foca-meta` для каждого файла (+ опциональный локальный OCR ML Kit во флейворе `play`) |
| 4 | `analysis` | Анализ | Люди, e-mail, ПК, ПО/EOL/KEV+CPE, секреты, маскируемые ПДн, находки, пути компрометации, риск |
| 5 | `network` | Сеть и DNS | DNS-сводка, поддомены из CT, посев прямых IP/CIDR, RDAP, InternetDB, TCP-живость, AXFR; SaaS/M365, почтовые политики, CDN, CT-история; перебор/перестановки/PTR/NSEC; TLS-инспекция; роли хостов |
| 6 | `ports` | Порты | TCP connect-скан, затем аудит TLS (устаревшие версии, STARTTLS, без SNI): только «Полный» |
| 7 | `recon` | Разведка сайта | Технологии, favicon, JS, веб-аудит, `robots`/`sitemap`/`security.txt`, бакеты, grep.app, опц. WebView-скриншоты (`pHash`); в «Полном»: ещё порты `8080/8443/3000/9000/5601/9200` |
| 8 | `fuzz` | Поиск на сайте | Перебор путей по словарю (только «Полный») |
| 9 | `report` | Отчёт | Итоги, снимок для «Что изменилось», срабатывание алертов мониторинга |

Этапы, не входящие в профиль, пропускаются мгновенно.

## Пауза, остановка, продолжение

- **Пауза/продолжение**, кнопкой на экране «Скан» или автоматически: обрыв сети, обрыв VPN/прокси (kill switch), низкий заряд, перегрев: решает политика ядра (`src-tauri/src/policy.rs`).
- **«Пропустить источник»**: у долго отвечающего источника (в т. ч. `subdomains` и `tls`); каждый поисковый источник дополнительно ограничен общим таймаутом.
- **Кнопки для каждого элемента:** пока идёт скан, этап, источник или шаг перебора в «Сеть и DNS» можно поставить на паузу, пропустить или перезапустить по отдельности: остальной скан продолжается. Перезапуск уже прошедшего этапа откладывается; после скана «Повторить отложенное» запускает только эти части.
- **Ход этапа «Сеть и DNS»:** виден текущий шаг со счётчиком (DNS-записи доменов, адреса поддоменов, проверка висячих CNAME, перебор поддоменов, перестановки имён, RDAP, проверка живости, сертификаты TLS). Если резолвер медленный (часто из-за VPN), появится предупреждение с ожидаемым временем перебора и кнопка «Пропустить перебор».
- **Остановка** сохраняет всё найденное. Остановленный или прерванный (выгрузка процесса) скан записывается как `stopped` и продолжается с места остановки (`scan_start { resume_from }`): уже скачанные документы и проверенные хосты повторно не трогаются.
